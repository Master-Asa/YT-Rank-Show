# 線上更新

在「統計與一般設定 → 軟體更新」手動檢查，或開啟自動檢查（預設關閉，每六小時至多一次；OneComme 啟用插件時背景執行）。不需要一直開著管理頁。不會自動安裝或強制關閉 OneComme。

只接受 Master-Asa/YT-Rank-Show 已公開的正式 Release，不接受草稿、Pre-release、相同版或降版。私人儲存庫會提示目前无法讀取公開版本，不收取或內建任何 GitHub 權杖。公開與正式 Release 發布流程仍需另行確認。

檢查／下載僅連線 GitHub；會傳送連線 IP、一般請求標頭與版本下載網址，不傳送支持紀錄、頻道設定、OBS 金鑰。版本與附件 SHA256 由 GitHub HTTPS API 取得，下載後比對雜湊並驗證 ZIP 路徑、大小及每檔 manifest。此方式信任 GitHub 帳號及發布流程，尚非獨立發行者數位簽章；應保護發布帳號與權限。

操作：檢查更新 → 下載更新 → 開啟更新視窗 → 自行關閉 OneComme → 備份與安裝 → 再開啟 OneComme。更新視窗等待最多 30 分鐘；尚未開始安裝前可關閉視窗取消。安裝中請勿重新開啟 OneComme。更新檔暫存在 AppData/Roaming/YT-Rank-Show/updates；備份保存在同層 upgrade-backups。設定與紀錄仍在 data，不會因更新而刪除。

更新失敗會顯示訊息；替換程式時遇到一般錯誤會嘗試還原舊版。停電、程序被強制終止等情況，可能需從備份人工還原。不要刪除更新資料夾與備份。暫存包與備份目前不會自動清除，以免誤刪復原材料。

## 怎麼測試

舊版 v0.8.x 沒有更新器，需要手動安裝一次包含更新器的版本。開發測試不將正式安裝版降級：使用 TEMP 下獨立的 yt-update-test-* 資料夾建立舊插件／假紀錄，以及注入到測試實例的 Release 資料與下載內容，檢查新版本選擇、下載毀損拒絕、路徑穿越拒絕、版本相同／降版拒絕及安裝後資料不變。

測試注入只存在於 Node 測試建構參數，不提供管理頁或 HTTP 測試網址。PowerShell 的 TestRoot/Headless 只允許 TEMP 下指定前綴的隔離目錄，不會跳過正式安裝的 OneComme 停止檢查。實際公開後，還應使用包含更新器的舊版在隔離 Windows 帳號或測試機，下載下一個正式 Release 做真實網路端到端驗證。
